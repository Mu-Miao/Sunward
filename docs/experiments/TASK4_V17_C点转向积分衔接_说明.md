# V17 TURN：V16 C点转向超限修复

2026-10-20，按用户要求修复V16的C点转向超限，保持正常路线连续运动、转向两轮正向目标及保护，完成编译。本版标题`TASK 4 V17 TURN`，用于区别板上V16。软件回归和ARM构建通过，本轮未烧录或进行V17实测。

## 实测问题与修改

V16采集会话`20261020_230428`已核对FLASH与V16 ELF完全匹配。本次选取启动时间`279339ms`的一趟：第一圈C点转向在120.108mm触发`YAW_BAD / T3_TURN(F8)`，采样时仍差约9.17°，电机命令已清零。CPU保持RUNNING，属于保护停车。9帧故障前后证据保存在[实测记录](records/task4/2026-10-20_v16_c_turn_limit.json)；RAM为20Hz异步读取，各字段不保证严格同时。

直线末段目标约195mm/s时，轮速约215/216mm/s，积分约1881/1868。切入20/80mm/s转向后，旧积分仍接近1880，之后内轮实速约50、外轮约100mm/s，造成转弯半径增大。原来的停止流程会清积分；V16取消停车后直接保留了直线积分。原条件积分PI只能逐步消退这部分积分。

V17增加一次性的`retarget_integrals`输出请求。连续模式在首次低速候选线确认、正常换段及首次可信全白桥接时请求衔接。端口生成并限幅新轮速目标后，对降速轮执行：

`新积分 = 旧积分 × 新目标速度 / 旧目标速度`

只处理新旧目标均正向且新目标更低的轮子，升速轮不增加积分。例如200→50mm/s时1800积分降至450，随后50→20mm/s时降至180。换段后的普通采样不重复缩减；正常巡线纠偏每帧不触发此操作。任务三、任务四可选停止流程不启用它。

衔接不调用`CarWheel_Clear()`或零驱动，不重置堵转/反向计时，不绕过原轮速PI。实际超速时PI仍可输出0让轮子减速滑行，不能为了保证某拍PWM非零而强推电机。
